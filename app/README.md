# SoundStaff

MIDI 파일을 브라우저에서 악보(PDF)와 MusicXML로 바꾸는 정적 웹앱. 서버·DB 없음, 파일은 외부로 전송되지 않는다.
기획서: `../PLAN.md`

## 개발 현황

| 단계 | 내용                                                    | 상태                                  |
| ---- | ------------------------------------------------------- | ------------------------------------- |
| M1   | 프로젝트 생성, 첨부 UI, MIDI 읽기, 트랙 목록            | 완료                                  |
| M2   | 양자화·마디 구성·MusicXML 생성 (악기별)                 | 완료 (Finale 확인됨)                  |
| M3   | 악보 표시(OSMD), PDF·MusicXML 다운로드                  | 완료                                  |
| M4   | (삭제) 피아노로 합치기 — 작성자 결정으로 제공하지 않음  | -                                     |
| M5   | 출력 단위 A/B, 설정 입력 칸, 피아노 MIDI, ZIP, PDF 설정 | 완료                                  |
| M6   | 음원 분석: 들리는 대로 악보(기본) / 멜로디만 (PC 전용)  | 완료 (멜로디 정확도 작성자 확인 대기) |
| M7   | 빌드 점검, 오류 처리 정리, 폰·태블릿 화면 점검          | 완료 (작성자 확인 대기)               |

## 실행

```bash
npm install
npm run dev       # 개발 서버
npm run build     # dist/ 정적 파일 생성 (타입 검사 포함)
npm test          # 자동 시험 (Vitest)
npm run lint      # 코드 검사 (oxlint)
npm run format    # 코드 모양 정리 (Prettier)
npm run check     # 타입 검사 + 코드 검사 + 자동 시험을 한 번에 (커밋 전에 실행)
```

### 배포 (M7)

`npm run build`가 만드는 `dist/` 폴더를 정적 호스팅(GitHub Pages, Netlify, 일반 웹서버 등)에 그대로 올리면 된다. 파일 경로가 상대 경로(`./assets/...`)라 **루트 주소든 하위 폴더 주소든** 동작한다(두 경우 모두 시험함). 서버 쪽 설정은 필요 없다. 단, 보안 규칙 때문에 `index.html`을 파일로 직접 열기(`file://`)는 지원하지 않으므로 간단히 확인할 때는 `npm run preview`나 `python3 -m http.server`처럼 웹서버로 띄운다. 방문 분석·광고 스크립트와 외부 글꼴은 쓰지 않는다(빌드 결과물에서 외부 요청 0건을 시험함).

#### 현재 배포 (Cloudflare Workers, GitHub 연결)

`main` 브랜치에 푸시하면 Cloudflare가 자동으로 빌드·배포한다. 주소는 https://soundstaff.itsolvers.co.kr 이다. 저장소에 설정 파일(`wrangler.jsonc`)은 없고, Cloudflare 대시보드(Compute → Workers & Pages → soundstaff → Settings → Builds)의 값으로 동작한다.

| 항목           | 값                                                                                      |
| -------------- | --------------------------------------------------------------------------------------- |
| 저장소         | `it-solvers/SoundStaff`, 브랜치 `main`                                                  |
| Root directory | `app` (칸이 없으면 아래 두 명령 앞에 `cd app &&`를 붙인다)                              |
| Build command  | `npm run build`                                                                         |
| Deploy command | `npx wrangler deploy --assets=./dist --name soundstaff --compatibility-date=2026-11-25` |
| 미리보기 빌드  | 끔 (설정 파일이 없어 `main` 외 브랜치는 배포 명령이 맞지 않을 수 있음)                  |

- `--name`은 Cloudflare 프로젝트 이름(`soundstaff`)과 같아야 한다. `--compatibility-date`는 Workers 실행 환경의 호환성 기준일이며 정적 파일만 올리는 이 앱의 동작에는 영향이 없다.
- 커스텀 도메인은 Workers & Pages → soundstaff → Domains → Add Domain에서 `itsolvers.co.kr`을 고르고 하위 이름 `soundstaff`을 붙여 연결했다(DNS 기록은 Cloudflare가 자동 생성). 직접 CNAME을 만들지 않는다.
- 푸시하기 전에 `data/`·`output/`(저작권 악보·음원, 개인 정보)가 커밋에 들어가지 않았는지 확인한다. 저장소가 공개이고 푸시가 곧 공개 배포이기 때문이다.

Node.js 20 이상. 커밋 전에는 `npm run check`가 통과해야 한다 (기획서 10.1장).

## 언어

한국어는 `/`(`index.html`), 영어는 `/en/`(`en/index.html`)이다. 화면 코드는 하나이고 `<html lang>`에 따라 `src/text/`의 `ko.ts`·`en.ts` 중 하나를 쓴다. 문구를 바꾸면 두 파일을 함께 고친다(항목이 빠지면 타입 검사에서 걸린다). `public/` 파일은 `src/utils/assetUrl.ts`로 가리킨다. 변경 이력은 한국어 화면에만 보인다.

## 동작 규칙 메모

- **출력 단위 A(합쳐서 하나)**: 템포·박자·조성은 첫 번째 파일 기준이고 다르면 경고한다. PPQ가 다른 파일은 첫 파일의 PPQ로 환산한다. (처리 방식은 기획서 13장에서 아직 확인 필요)
- **설정 입력**: 값이 없으면 MIDI 값을 쓴다. 템포·박자를 직접 입력하면 파일의 변화 정보는 그 값 하나로 바뀐다. 값을 바꾸면 이미 만든 악보는 자동으로 다시 만든다.
- **피아노 MIDI**: 원본의 모든 음높이 트랙을 피아노(프로그램 0)로 통일하고 드럼은 뺀다. 악보용 양자화를 거치지 않아 음이 빠지지 않는다.
- **제목·작곡자**: PDF와 MusicXML에 기록한다. MusicXML의 제목·작곡자는 `credit`에 맑은 고딕(Malgun Gothic)을 지정해 Finale(Windows)에서 한글이 깨지지 않게 한다.
- **PDF**: A4 세로·가로, 악보 크기 작게(0.75)·보통(1.0)·크게(1.3), 쪽 번호. 한글(제목·트랙 이름·작곡자)은 글꼴을 내장하지 않고 `public/fonts`의 글꼴에서 글자 모양을 읽어 **윤곽선(경로)으로 그린다**(`outlineText.ts`). 글꼴 내장은 PDF 뷰어에 따라 한글이 빠져 보이는 문제가 있었다. 대신 그 글자는 PDF에서 복사·검색할 수 없다.

## 악기 설정: 순서·소리 끄기·빼기 (`src/score/trackOrder.ts`, `components/TrackOrder.tsx`)

- 악보에서 악기(트랙) 단이 위에서 아래로 쌓이는 순서를 사용자가 정한다. 합쳐서 악보 하나로 만들 때뿐 아니라 여러 트랙이 든 MIDI 한 개에도 쓴다(악기가 2개 이상일 때만 목록이 보인다).
- 값은 `SettingsOverride.trackOrder`(트랙 번호 목록)이고 `ScoreSettings.trackOrder`로 넘어가 `buildInstrumentScore`가 `orderBy`로 단을 정렬한다. 비어 있으면 원래 순서(파일 순서 → 파일 안 트랙 순서). 목록에 없는 트랙은 원래 순서로 맨 뒤에 붙고, 없는 번호·중복은 무시한다.
- 화면: 끌어서 옮기기(HTML5 끌어놓기, PC)와 ▲▼ 버튼(터치 기기·키보드, 높이 36px 이상), [원래 순서로]. 순서를 바꾸면 이미 만든 악보는 자동으로 다시 만들어진다. 재생·PDF·MusicXML은 같은 악보 모델을 쓰므로 순서가 그대로 따른다.
- **소리 끄기**(`mutedTracks`, 버튼은 직접 그린 스피커 그림: 켜짐 = 스피커 + 소리 물결, 꺼짐 = 스피커 + ✕와 주황색. 이모지는 작고 흐려서 쓰지 않는다): 악보(MusicXML·PDF)는 그대로이고 `PartModel.muted`만 붙어 재생 시간표(`timeline.ts`)에서 그 악기를 뺀다. 곡 길이·커서는 그대로. 모두 끄면 재생 버튼이 꺼진다.
- **악보에서 빼기**(`excludedTracks`): `prepare()`가 처음부터 없는 악기로 쳐서 마디 수·경고·악보·재생·PDF·MusicXML 모두에서 빠진다. 뺀 악기는 "악보에서 뺀 악기" 칸에서 [다시 넣기]. 악기를 모두 빼면 오류 문구가 나오고, 화면은 마지막 한 악기의 ✕를 꺼 둔다. [원래대로]는 순서·소리 끄기·뺀 악기를 모두 되돌린다.
- **한계**: 악기 이름을 바꾸는 기능은 아직 없다. 터치 기기에서는 끌어서 옮기기가 되지 않아 ▲▼ 버튼을 쓴다.

## 악보 재생 (`src/play/`)

- **무엇을 재생하나**: 원본 MIDI가 아니라 **악보 모델**(`ScoreModel`: 칸에 맞춘 음 길이, 사용자가 고친 템포·박자)이다. 그래서 눈에 보이는 악보와 들리는 소리를 비교해 틀린 곳을 찾을 수 있다. 붙임줄은 한 음으로 합치고 쉼표는 무음이다.
- `timeline.ts`: 악보 → 초 단위 음 목록, 시간 ↔ 칸 위치 변환(템포는 마디 시작에서만 바뀜, 없으면 120BPM). `synth.ts`: 합성음 6종(합성 피아노·오르간·현악·플루트·종·하프시코드, 배음 구성 + 소리 크기 변화 + 떨림). `pianoSamples.ts`: 실제 피아노 소리(public/piano의 Salamander Grand Piano mp3 30개, CC BY 3.0, 곡에서 쓰는 음역만 불러와 모노·10초로 줄이고 음량을 맞춤). `player.ts`: 재생·일시정지·이어서·정지, 앞으로 1.5초 안의 음만 미리 예약해 긴 곡도 가볍다.
- **악보 커서**: OSMD 커서를 쓴다. 재생 위치(초)를 16분음표 칸으로 바꿔 커서가 멈출 칸 목록(`draw()`가 모음)에서 찾아 옮기고, 화면 밖이면 스크롤한다. 긴 제목을 여러 줄로 나누면 악보가 아래로 내려가므로 커서도 같은 만큼 내린다(`wrapTitle`이 늘어난 높이를 돌려줌).
- **한계**: 피아노 한 가지 소리만 낸다(악기별 음색 없음, 드럼 제외). 악보를 눌러 그 위치부터 재생하는 기능은 아직 없다(처음부터만). 속도는 재생을 시작할 때만 고를 수 있다. 소리는 이 브라우저의 소리 장치로 나가며 서버로 보내지 않는다.

## 음원 분석 (M6) 규칙 메모

- **주파수 보정**(`audio/spectrum.ts`, 분석 작업 스레드 안): AI(Basic Pitch)는 섞인 소리에서 음을 자주 놓치고 낮은 음을 잘못 넣는다(시험곡: 실제로 들리는 음의 61%만 찾음). 그래서 거른 음을 소리의 주파수 분석(창 8192, 반음마다 기본음 크기, 낮은 음의 배음은 제외)과 대조해 ① 소리가 거의 없는 높이의 음을 빼고 ② 같은 높이가 0.74초 이상(8프레임) 들리고 가장 센 음의 55% 이상인데 빠진 음을 세기 0.3으로 넣고 ③ 찾은 음 앞뒤로 이어서 들리면 그 음을 늘린다. 시험곡 61%→85%는 같은 소리의 주파수 분석을 기준으로 잰 값이라 넣는 쪽에 유리하다(순환 측정). 정답이 있는 시험(`tools/typebench`의 합성 시험곡 13개, `tools/benchmark`의 정답 악보)에서는 너무 많이 넣으면 오히려 점수가 내려가서, 넣는 조건을 엄격하게 바꿨다(합성곡 평균 음높이 F1 56%→63%, 실제 곡 0.706→0.741).
- **박 추적**(`audio/beats.ts`, 분석 작업 스레드 안): 연주가 느려지거나 빨라지는 곡(rit.)에서 고정 템포로는 박이 밀린다(시험곡 8~11마디가 한 박 밀림). 온셋 곡선에서 동적 계획법으로 박의 시각을 추적하고(간격 허용 0.9~2배, 느슨하면 박을 끼워 넣어 오히려 나빠짐) 시각→박 위치로 바꾼다. 템포가 6% 이상 바뀐 마디에만 템포 표시를 넣고, 사용자가 템포를 고치면 쓰지 않는다. 시험곡 음이름 F1 0.90 → 0.95.
- **편집용 정리**(`audio/editTuning.ts`, `midi/quantize.ts`의 `tidyForEditing`): Finale에서 고치기 쉽게 같은 음 이어 붙이기·8분음표 칸·박 단위 화음(한 보표 한 성부)·음별 붙임줄·배음 거르기를 한다. 조정값은 `EditTuning`에 모여 있고 정답 악보 비교로 맞췄다(화면에서는 바꿀 수 없음).
- **정답 악보(PDF) 평가**(`tools/benchmark/`, 파이썬 표준 라이브러리): 벡터 PDF 악보에서 음표를 복원해 변환 결과와 박마다 비교한다. 사용법은 `tools/benchmark/README.md`. 저작권이 있는 악보·음원은 저장소에 올리지 않는다.
- **악보 방식 두 가지** (`AudioMode`, 기본 `full`): **들리는 대로**는 AI가 찾은 모든 음(거른 뒤)을 쓴다. 가온 도(60) 이상은 오른손(높은음자리표), 미만은 왼손(낮은음자리표)으로 나눈다(`audioTracks`, 한쪽이 비면 한 단, 번호는 오른손 0/왼손 1 고정). 기본 흐름(`buildScore.prepare` → `buildInstrumentScore`):
  (기본으로 켜진 **[고치기 쉽게]**(`audioEdit`)가 적용되면 아래 1~3 대신 아래의 **편집용 정리**가 쓰인다. 아래 1~3은 [고치기 쉽게]를 껐을 때의 방식이다.)
  1. **같은 음 이어 붙이기**(`mergeRepeatedNotes`, `audioMerge`, 기본 켬): 같은 높이로 **0.1초 이내**에 이어지거나 겹친 음은 하나로. AI는 길게 울리는 한 음을 떨림(트레몰로·비브라토)으로 소리 크기가 출렁일 때 중간에 새 음으로 끊어 낸다(시험곡: 같은 높이의 다음 음까지 간격 0.05초 이하가 351개, 0.05~0.2초가 66개).
  2. **주된 음 표시**(`markMinorNotes`, `audioEmphasis`, 기본 켬): 중요도(세기 × √길이)가 낮은 아래쪽 40%를 덜 주된 음(`minor`)으로 표시. 다시 `selectMainNotes`가 중요한 음부터 **성부 3개 안에** 자리를 잡아 주고 자리 없는 음은 덜 주된 음으로 돌린다. 덜 주된 음은 MusicXML `<note color="#8a8a8a">`로 회색이 된다(악보 미리보기·PDF에서 보임, Finale에서는 색이 안 보일 수 있음).
  3. **읽기 쉽게 정리**(`simplifyToChords`, `audioSimplify`, 기본 켬): 주된 음은 성부로 나눠 적되 길이를 지키고(겹치면 최대 3성부), 덜 주된 음만 한 성부 화음(최대 4음, 다음 화음 시작에서 끊김)으로 단순화한다. 한 보표 최대 4성부이며, 자리가 없는 회색 음만 뺀다(`fitMinorToVoices`, 알림에 개수 표시). 돋보이기를 끄면 모든 음을 한 성부 화음으로 정리한다(주된 음 길이가 많이 줄어듦: 시험곡 29%).
  4. **피아노 대보표**: 정리가 켜져 있으면 오른손·왼손을 한 파트 `Piano`의 두 보표(`<staves>2`, 중괄호)로 묶는다. 순서는 오른손 위·왼손 아래로 고정이고 보표별 소리 끄기·빼기는 가능하다(`StaffModel.muted`).
     정리를 끄면 이전의 **무손실** 방식이다: 칸에 맞춘 음을 여러 성부로 적고 4성부를 넘으면 같은 음자리표의 추가 단(`splitIntoLayers`, "오른손 (높은 음) 2")으로 보낸다(층은 레가토 정리를 끄고 배치. 두 번 하면 긴 음이 칸마다 줄어든다). 찾은 음이 악보에 모두 있는지는 `tests/helpers.ts`의 `transcriptionCoverage`(이어 붙이기를 끈 경우: 같은 높이, 시작 오차 1칸 이내)와 `soundingCoverage`(켠 경우)로 시험한다. 시험곡(우리 기도를) 측정: 합친 음 257개의 시작은 모든 방식에서 100% 악보에 있고, 주된 음의 길이 유지율은 기본 86%, 돋보이기를 끈 1성부 29%, 무손실 94%. **멜로디만**은 아래 선택 규칙으로 한 줄(높은음자리표 한 단, 파트 "Melody")을 만든다. 방식을 바꾸면 악기 설정(순서·소리 끄기·빼기)은 처음으로 돌아간다. 출력 단위 선택은 MIDI에만 적용한다.
- **왜 기본이 들리는 대로인가**: 관현악+피아노 아르페지오 곡으로 확인했더니 멜로디 한 줄 선택은 소프라노(Eb4)를 찾고도 오래 이어지는 낮은 반주 음(G3)을 골랐다. 멜로디가 무엇인지는 소리만으로 정할 수 없어서 선택에 의존하지 않는 방식을 기본으로 했다. 조성·템포 추정도 모든 음을 기준으로 해서 안정적이다(같은 곡에서 멜로디 기준 G단조 → 모든 음 기준 Eb장조로 정확).
- **순서**: 읽기 → 모노 22,050Hz → Basic Pitch(작업 스레드) → 짧거나 불확실한 음 거르기 → 템포·조성 추정(모든 음 기준) → (이후 MIDI와 같은 양자화·마디·MusicXML) → 들리는 대로: 두 단 화음 정리 / 멜로디만: **주 멜로디 선택**과 한 줄 보장.
- **주 멜로디 선택**(멜로디만 방식, `melody.ts`, 기획서 8.5장 4단계): ① 음역 C3~G5(MIDI 48~79)만 후보 ② 같은 시간에 여러 음이면 `신뢰도 × 음 지속시간` 점수가 가장 높은 음 ③ 직전 음보다 1옥타브 이상 튄 짧은 음(0.8초 미만)은 직전 음 가까운 옥타브로 보정(튄 뒤에도 그 높이에 머무는 진짜 도약은 그대로) ④ 같은 높이가 50ms 이내 틈이면 하나로 합침. 0.08초 미만 조각은 이웃에 합친다. 기준값은 시험하며 조정한다.
- **템포**: 파형(스펙트럼 플럭스)의 자기상관으로 추정하고, 확신이 낮으면 음표 간격으로 보완한다. 음표를 초 단위로 보관하고 악보를 만들 때 지금 템포로 박 위치를 환산하므로, 템포를 고치면 박 구조가 다시 만들어진다.
- **상한**: 음원 50MB, 10분. 분석 전에 크기·길이·브라우저 메모리를 검사한다.
- **폰·태블릿**: 너비 768px 미만, 또는 터치 기기이면서 1024px 미만, 또는 브라우저가 모바일이라고 알릴 때. 음원 메뉴를 숨기고 AI 모델을 내려받지 않는다.
- **작업 스레드에는 `window`가 없다**: AI 라이브러리가 찾는 `window`를 `workers/shim.ts`가 먼저 채운다. 이게 없으면 분석이 멈춘다.

- **긴 곡 제목**: OSMD는 제목을 한 줄만 그려서 길면 잘린다. `score/wrapTitle.ts`가 쪽 폭에 맞춰 글자를 줄여(원래의 100~50%) 2줄 안에 맞추고, 그래도 안 되면 최대 6줄로 나눈다(`layoutTitle`, 단위 시험 있음). 줄마다 쪽 가운데에 다시 놓고 아래 내용을 내린다(미리보기·PDF 공통, PDF는 실제 그릴 한글 글꼴로 폭을 잰다).

- **밝은/다크 모드**: `src/theme/`. 자동은 인천 동구 일대 좌표(`sun.ts`, 소수 둘째 자리)로 일출·일몰을 이 기기 안에서 계산해(NOAA 일출 방정식) 낮이면 밝게, 밤이면 어둡게 한다. 30초마다 다시 확인한다. 선택은 `localStorage`(`soundstaff-theme`)에 저장하며, 저장소를 못 쓰면 자동이다. 밝은 모드 색은 `index.css`에서 Tailwind 팔레트의 진한 쪽과 연한 쪽을 맞바꿔 만든다(`:root[data-theme='light']`, 흰 글씨를 쓰는 500~700 단계는 그대로). 새 색 계열을 쓰면 이 목록에 추가해야 한다. 악보 미리보기 글씨 색은 `ScoreView.tsx`의 `INK`.

- **위쪽 고정 영역**: 제목·언어·화면 색과 단계 막대(`StepBar.tsx`)를 `App.tsx`의 `top-bar` 한 덩어리로 `sticky`에 둔다. 스크롤에 따라 높이나 가로 배치가 바뀌지 않아야 한다(요소가 밀리거나 툭 나타나 보인다).

- **악보는 자동으로 만든다**: [악보 만들기] 버튼은 없다. 첨부하면 `handleFiles`가 MIDI를 읽자마자(음원은 분석이 끝나면) `deriveItems` → `buildState`로 악보까지 만들고, 출력 단위(`changeUnit`)·설정·악기 설정(`changeSettings`)을 바꾸면 항상 다시 만든다. 사용 방법은 4단계(첨부 → 다듬기(선택) → 확인하고 저장 → 편집)이고 `App.tsx`의 `step`은 파일 없음 1 / 읽기만 됨 2 / 악보 있음 3이다. 악보 아래 알림 목록(`ScoreResult`)은 `<details>`로 기본 접혀 있다.

- **마우스 올림(hover) 색**: 밝은 화면은 팔레트의 진한 쪽(500~700)을 그대로 두므로, 글자색이 뒤집히는 버튼(`text-slate-200` 등)에 `hover:bg-slate-700`처럼 진한 색을 쓰면 밝은 화면에서 글자와 배경이 같은 색이 된다. 이런 버튼은 반투명 회색(`hover:bg-slate-500/20`)을 쓰고, 흰 글씨 버튼은 마우스를 올리면 더 진해지게 한다. 모든 버튼에 마우스를 올려 대비를 재는 시험으로 확인했다.

## 알려진 사항

- **음원 분석의 정확도 한계**: 악기 하나(또는 보컬만 분리한 파일)에서는 정확하지만(시험: 단선율 16음이 WAV·M4A·FLAC·MP3에서 모두 같은 높이·시작·길이로 복원), 여러 악기가 섞이면 반주 음을 멜로디로 잘못 고를 수 있다. 가장 높은 음을 따르므로 멜로디 위에 화음이 있으면 그 화음 음을 따라간다. 조성 추정도 섞인 음원에서는 틀릴 수 있다(시험: 합창+관현악 합성음에서 Eb장조를 G단조로 추정, 템포 82는 정답). 그래서 [악보 설정]에서 고칠 수 있게 하고 "추정"으로 표시한다.
- OGG는 이 환경에 인코더가 없어 시험하지 못했다 (mp3, wav, m4a, flac은 시험함).

- **음원(mp3, wav) 분석은 아직 없다** (M6). 소개 문구도 그래서 "MIDI 파일을…"로 쓰고, M6이 끝나면 기획서 원문("음원이나 MIDI 파일을…")으로 바꾼다.
- 전체 ZIP은 **2단계**(만들기 → 저장 링크 클릭)다. 만드는 데 몇 초 걸려서 바로 내려받게 하면 Chrome이 "클릭 없는 자동 다운로드"로 보고 막기 때문이다.
- 악보 그리기(OSMD)와 PDF 라이브러리는 필요할 때 불러온다. 첫 화면 JS는 약 309KB(압축 98KB)다.
- `@tonejs/midi`의 **쓰기** 기능은 조표를 잘못 기록한다 (읽기는 정상). 피아노 MIDI는 조표 바이트를 직접 고쳐 쓴다 (`exportPianoMidi.ts`).
- MIDI 텍스트(트랙 이름)는 인코딩이 규격에 없어, UTF-8·EUC-KR 복원을 시도한다.
- 3연음(셋잇단 8분·4분음표)은 인식해 적고, 그 밖에 16분음표 격자에 맞지 않는 리듬(5연음 등)은 가까운 자리로 맞춘다. 시작 위치가 격자에서 크게 벗어난 음표가 10%를 넘으면 경고한다.
- 마디 중간의 템포 변화는 가장 가까운 마디 시작으로 옮긴다 (경고 표시). 세기(velocity), 페달, 피치 벤드는 악보에 반영하지 않는다.
- **한글 파일 이름은 NFC(합쳐진 형태)로 바꿔 쓴다.** 맥은 파일 이름을 자음·모음이 분리된 형태(NFD)로 돌려주는 경우가 있는데, 이 글자는 PDF용 글꼴에 없어 제목에서 한글이 지워지고 Finale에서도 제목이 깨진다. 파일 이름·트랙 이름·입력한 제목·PDF에 그리는 글자 모두에서 바꾼다 (`readMidi.ts`, `settings.ts`, `outlineText.ts`, 회귀 시험 있음).
- opentype.js 2.0의 글자열 배치·경로 변환(`getPath`, `toPathData`)은 세 글자 이상에서 `NaN`을 만드는 경우가 있어, 글자를 하나씩 이어 붙이고 경로 문자열을 직접 쓴다 (`outlineText.ts`, 회귀 시험 있음).
- OSMD는 템포 표시만 `14pt`·`times`·`xml:space="preserve"`로 그려서 svg2pdf가 PDF에 숫자를 빠뜨린다. `exportPdf.ts`의 `normalizeText`가 변환 직전에 형식을 맞춘다. OSMD를 올릴 때 다시 확인할 것.
- 브라우저 화면 시험(Playwright)은 아직 저장소에 없다. 자동 시험은 로직(Vitest)만 있고, 화면은 개발 중 따로 시험했다.

## 개발 검증 메모

MusicXML은 공식 3.1 스키마(`musicxml.xsd`, https://github.com/w3c/musicxml 의 `v3.1` 태그)를 `xmllint --noout --nonet --schema`로 검사해 통과를 확인했다 (앱에는 포함하지 않음).

PDF 글꼴: 한글 제목·트랙 이름이 깨지지 않도록 `public/fonts/SoundStaffKR-Regular.ttf`(NanumGothic에서 영문·한글 음절만 남긴 부분 글꼴, 약 1.3MB)를 PDF를 만들 때만 내려받아 내장한다.

## 검증 방법

앱에 포함하지 않는 개발용 검증: 공식 MusicXML 3.1 스키마(`musicxml.xsd`, https://github.com/w3c/musicxml 의 `v3.1` 태그)를 `xmllint --noout --nonet --schema`로 검사.

## 사용 환경 (작성자)

Finale 27.4 (Windows). 제목 글꼴은 MusicXML의 `credit-words`에 맑은 고딕(Malgun Gothic)으로 지정한다 (`src/score/toMusicXml.ts`). 한글 제목 정상 표시를 Finale에서 확인함.
화면은 다크 모드 전용이며, 미리보기 악보만 밝은 색으로 그린다. PDF는 흰 종이·검은 악보로 별도 생성한다.

## 알려진 사항

- opentype.js 2.0의 글자열 배치·경로 변환(`getPath`, `toPathData`)은 세 글자 이상에서 `NaN`을 만드는 경우가 있어, 글자를 하나씩 이어 붙이고 경로 문자열을 직접 쓴다 (`outlineText.ts`, 회귀 시험 있음).
- OSMD는 템포 표시만 `14pt`·`times`·`xml:space="preserve"`로 그려서 svg2pdf가 PDF에 숫자를 빠뜨린다. `exportPdf.ts`의 `normalizeText`가 변환 직전에 형식을 맞춘다. OSMD를 올릴 때 다시 확인할 것.
- 처음 내려받는 JS는 약 336KB(gzip 107KB)이고, 악보 그리기(OSMD, 약 1.5MB)·PDF 만들기(약 0.7MB)·음원 분석(AI, 약 1.8MB + 모델)은 쓸 때만 내려받는다 (M7 확인).

- `@tonejs/midi`의 **쓰기** 기능은 조표를 잘못 기록하는 문제가 있다 (읽기는 정상). 피아노 MIDI 저장(M5) 때 조표 기록은 직접 검증한다.
- MIDI 텍스트(트랙 이름)는 인코딩이 규격에 없어, UTF-8·EUC-KR 복원을 시도한다 (`src/midi/readMidi.ts`).
- 3연음(셋잇단 8분·4분음표)은 인식해 적고, 그 밖에 16분음표 격자에 맞지 않는 리듬(5연음 등)은 가까운 자리로 맞춘다. 시작 위치가 격자에서 크게 벗어난 음표가 10%를 넘으면 경고를 표시한다.
- 마디 중간의 템포 변화는 가장 가까운 마디 시작으로 옮긴다 (경고 표시).
- 세기(velocity), 페달, 피치 벤드는 악보에 반영하지 않는다.
- 성부는 먼저 시작한 음이 1성부가 된다. 낮은 음이 먼저 시작하면 그 뒤 선율이 2성부(줄기 아래 방향)가 될 수 있다.
