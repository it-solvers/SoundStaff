# SoundStaff

MIDI 파일을 브라우저에서 악보(PDF)와 MusicXML로 바꾸는 정적 웹앱. 서버·DB 없음, 파일은 외부로 전송되지 않는다.
기획서: `../PLAN.md`

## 개발 현황

| 단계 | 내용                                                        | 상태                                  |
| ---- | ----------------------------------------------------------- | ------------------------------------- |
| M1   | 프로젝트 생성, 첨부 UI, MIDI 읽기, 트랙 목록                | 완료                                  |
| M2   | 양자화·마디 구성·MusicXML 생성 (악기별)                     | 완료 (Finale 확인됨)                  |
| M3   | 악보 표시(OSMD), PDF·MusicXML 다운로드                      | 완료                                  |
| M4   | 피아노로 합치기 + 제거 음 표시                              | 완료 (Finale 확인됨)                  |
| M5   | 출력 단위 A/B, 설정 입력 칸, 피아노 MIDI, ZIP, PDF 설정     | 완료                                  |
| M6   | 음원 분석: 주 멜로디만 한 단 악보로 (PC 전용), Colab 안내판 | 완료 (멜로디 정확도 작성자 확인 대기) |
| M7   | 빌드 점검, 오류 처리 정리, 폰·태블릿 화면 점검              | 완료 (작성자 확인 대기)               |

## 실행

```bash
npm install
npm run dev       # 개발 서버
npm run build     # dist/ 정적 파일 생성 (타입 검사 포함)
npm test          # 자동 시험 (Vitest)
npm run lint      # 코드 검사 (oxlint)
npm run format    # 코드 모양 정리 (Prettier)
npm run check     # 타입 검사 + 코드 검사 + 자동 시험을 한 번에 (커밋 전에 실행)
```

### 배포 (M7)

`npm run build`가 만드는 `dist/` 폴더를 정적 호스팅(GitHub Pages, Netlify, 일반 웹서버 등)에 그대로 올리면 된다. 파일 경로가 상대 경로(`./assets/...`)라 **루트 주소든 하위 폴더 주소든** 동작한다(두 경우 모두 시험함). 서버 쪽 설정은 필요 없다. 단, 보안 규칙 때문에 `index.html`을 파일로 직접 열기(`file://`)는 지원하지 않으므로 간단히 확인할 때는 `npm run preview`나 `python3 -m http.server`처럼 웹서버로 띄운다. 방문 분석·광고 스크립트와 외부 글꼴은 쓰지 않는다(빌드 결과물에서 외부 요청 0건을 시험함).

Node.js 20 이상. 커밋 전에는 `npm run check`가 통과해야 한다 (기획서 10.1장).

화면 제목 옆 `(1.6.1)`과 브라우저 탭 제목에 버전이 표시된다. 기능을 추가하거나 화면을 바꿀 때마다 올린다.

| ------------------------------ | ----------- | ------------- |
| 기능 추가                      | 두 번째     | 1.0.0 → 1.1.0 |
| 화면 문구·배치 변경, 버그 수정 | 세 번째     | 1.1.0 → 1.1.1 |

올리는 방법: `package.json`의 `version`과 `src/changelog.ts` 맨 위에 새 항목을 **같은 값으로** 함께 바꾼다. 두 값이 다르면 개발 서버·빌드가 멈추고 알려 준다. 화면 하단 "변경 이력"에 `changelog.ts`의 내용이 보인다.

## 동작 규칙 메모

- **피아노 합치기**: 가온 도(60) 이상은 오른손, 미만은 왼손. 경계를 넘나드는 한 줄 선율은 한 손에 고정. 한 손 동시 5음·음 폭 10도(16반음) 이내로 정리하며 선율(오른손 최고음) > 베이스(왼손 최저음) > 안쪽 화음 순으로 남긴다. 중복(같은 시작·같은 높이)은 하나로 합치고, 제거한 음 수를 화면에 표시한다.
- **출력 단위 A(합쳐서 하나)**: 템포·박자·조성은 첫 번째 파일 기준이고 다르면 경고한다. PPQ가 다른 파일은 첫 파일의 PPQ로 환산한다. (처리 방식은 기획서 13장에서 아직 확인 필요)
- **설정 입력**: 값이 없으면 MIDI 값을 쓴다. 템포·박자를 직접 입력하면 파일의 변화 정보는 그 값 하나로 바뀐다. 값을 바꾸면 이미 만든 악보는 자동으로 다시 만든다.
- **피아노 MIDI**: 원본의 모든 음높이 트랙을 피아노(프로그램 0)로 통일하고 드럼은 뺀다. 악보용 양자화를 거치지 않아 음이 빠지지 않는다.
- **제목·작곡자**: PDF와 MusicXML에 기록한다. MusicXML의 제목·작곡자는 `credit`에 맑은 고딕(Malgun Gothic)을 지정해 Finale(Windows)에서 한글이 깨지지 않게 한다.
- **PDF**: A4 세로·가로, 악보 크기 작게(0.75)·보통(1.0)·크게(1.3), 쪽 번호. 한글(제목·트랙 이름·작곡자)은 글꼴을 내장하지 않고 `public/fonts`의 글꼴에서 글자 모양을 읽어 **윤곽선(경로)으로 그린다**(`outlineText.ts`). 글꼴 내장은 PDF 뷰어에 따라 한글이 빠져 보이는 문제가 있었다. 대신 그 글자는 PDF에서 복사·검색할 수 없다.

## 음원 분석 (M6) 규칙 메모

- **주 멜로디 한 단만** 만든다. 화음·반주·여러 악기는 만들지 않고 작곡가가 편곡한다 (기획서 8.5장). 결과는 항상 높은음자리표 한 단, 파트 이름 `Melody`, 겹치는 음 없는 한 줄이다. 출력 단위·변환 방식은 MIDI에만 적용한다.
- **순서**: 읽기 → 모노 22,050Hz → Basic Pitch(작업 스레드) → 짧거나 불확실한 음 거르기 → **주 멜로디 선택** → 템포·조성 추정 → (이후 MIDI와 같은 양자화·마디·MusicXML) → 한 줄 보장.
- **주 멜로디 선택**(`melody.ts`, 기획서 8.5장 4단계): ① 음역 C3~G5(MIDI 48~79)만 후보 ② 같은 시간에 여러 음이면 `신뢰도 × 음 지속시간` 점수가 가장 높은 음 ③ 직전 음보다 1옥타브 이상 튄 짧은 음(0.8초 미만)은 직전 음 가까운 옥타브로 보정(튄 뒤에도 그 높이에 머무는 진짜 도약은 그대로) ④ 같은 높이가 50ms 이내 틈이면 하나로 합침. 0.08초 미만 조각은 이웃에 합친다. 기준값은 시험하며 조정한다.
- **템포**: 파형(스펙트럼 플럭스)의 자기상관으로 추정하고, 확신이 낮으면 음표 간격으로 보완한다. 음표를 초 단위로 보관하고 악보를 만들 때 지금 템포로 박 위치를 환산하므로, 템포를 고치면 박 구조가 다시 만들어진다.
- **상한**: 음원 50MB, 10분. 분석 전에 크기·길이·브라우저 메모리를 검사한다.
- **폰·태블릿**: 너비 768px 미만, 또는 터치 기기이면서 1024px 미만, 또는 브라우저가 모바일이라고 알릴 때. 음원 메뉴를 숨기고 AI 모델을 내려받지 않는다.
- **작업 스레드에는 `window`가 없다**: AI 라이브러리가 찾는 `window`를 `workers/shim.ts`가 먼저 채운다. 이게 없으면 분석이 멈춘다.

- **고품질 변환(Colab) 3단계 안내판**(`ColabGuide.tsx`): ① Colab 열기(작은 창으로 화면 오른쪽에 띄움, `colabWindow.ts`. Colab은 로그인이 필요해 iframe으로 끼울 수 없다. 팝업이 막히면 새 탭으로 대체) ② 받기 ③ 돌아와서 MIDI 놓기를 한 자리에 모았다. Colab 창이 닫히면(창 닫힘을 0.5초마다 확인) ③번 상자를 강조하고 화면에 보이게 한다. ③번에 놓은 MIDI는 [악보 만들기] 없이 바로 악보까지 만들고(`handleFiles(files, true)`) 악보 위치로 스크롤한다. 시험용으로는 환경변수 `VITE_COLAB_URL`로 주소를 줄 수 있다.
- **고품질 변환(Colab) 버튼**: `src/config.ts`의 `COLAB_URL`에 노트북 주소를 넣으면 켜진다(기획서 13장 18번). 비어 있으면 "준비 중"으로 표시한다. 사용자가 직접 클릭해 새 탭으로 여는 링크일 뿐 파일은 전송하지 않는다.
- **긴 곡 제목**: OSMD는 제목을 한 줄만 그려서 길면 잘린다. `score/wrapTitle.ts`가 쪽 폭에 맞춰 최대 4줄로 나누고 아래 내용을 내린다(미리보기·PDF 공통, PDF는 실제 그릴 한글 글꼴로 폭을 잰다).

- **밝은/다크 모드**: `src/theme/`. 자동은 인천 동구 일대 좌표(`sun.ts`, 소수 둘째 자리)로 일출·일몰을 이 기기 안에서 계산해(NOAA 일출 방정식) 낮이면 밝게, 밤이면 어둡게 한다. 30초마다 다시 확인한다. 선택은 `localStorage`(`soundstaff-theme`)에 저장하며, 저장소를 못 쓰면 자동이다. 밝은 모드 색은 `index.css`에서 Tailwind 팔레트의 진한 쪽과 연한 쪽을 맞바꿔 만든다(`:root[data-theme='light']`, 흰 글씨를 쓰는 500~700 단계는 그대로). 새 색 계열을 쓰면 이 목록에 추가해야 한다. 악보 미리보기 글씨 색은 `ScoreView.tsx`의 `INK`.

## 고품질 변환 노트북 (Colab)

`../colab/soundstaff_hq_convert.ipynb`: 사용자가 자기 구글 계정의 무료 GPU에서 ① 음원 올리기 ② 반주 제거(Demucs, MIT) ③ MIDI 변환(Basic Pitch, Apache-2.0) ④ MIDI 내려받기를 칸 순서대로 실행하는 노트북이다. 앱의 [고품질 변환(Colab) 열기]는 GitHub에 올라간 이 파일을 Colab에서 여는 주소(`src/config.ts`)다. 파일 이름·위치를 바꾸면 `config.ts`도 같이 바꿔야 하며, 자동 시험(`tests/colab.test.ts`)이 둘이 맞는지 확인한다. **이 노트북은 Colab에서 직접 실행해 보지 못했다(작성 환경에 Colab이 없음).** 도구 버전이 올라가 설치·실행이 깨지면 노트북의 1번 칸(설치)과 4번 칸(Demucs 호출)부터 확인한다.

## 알려진 사항

- **음원 분석의 정확도 한계**: 악기 하나(또는 보컬만 분리한 파일)에서는 정확하지만(시험: 단선율 16음이 WAV·M4A·FLAC·MP3에서 모두 같은 높이·시작·길이로 복원), 여러 악기가 섞이면 반주 음을 멜로디로 잘못 고를 수 있다. 가장 높은 음을 따르므로 멜로디 위에 화음이 있으면 그 화음 음을 따라간다. 조성 추정도 섞인 음원에서는 틀릴 수 있다(시험: 합창+관현악 합성음에서 Eb장조를 G단조로 추정, 템포 82는 정답). 그래서 [악보 설정]에서 고칠 수 있게 하고 "추정"으로 표시한다.
- OGG는 이 환경에 인코더가 없어 시험하지 못했다 (mp3, wav, m4a, flac은 시험함).

- **음원(mp3, wav) 분석은 아직 없다** (M6). 소개 문구도 그래서 "MIDI 파일을…"로 쓰고, M6이 끝나면 기획서 원문("음원이나 MIDI 파일을…")으로 바꾼다.
- 전체 ZIP은 **2단계**(만들기 → 저장 링크 클릭)다. 만드는 데 몇 초 걸려서 바로 내려받게 하면 Chrome이 "클릭 없는 자동 다운로드"로 보고 막기 때문이다.
- 악보 그리기(OSMD)와 PDF 라이브러리는 필요할 때 불러온다. 첫 화면 JS는 약 309KB(압축 98KB)다.
- `@tonejs/midi`의 **쓰기** 기능은 조표를 잘못 기록한다 (읽기는 정상). 피아노 MIDI는 조표 바이트를 직접 고쳐 쓴다 (`exportPianoMidi.ts`).
- MIDI 텍스트(트랙 이름)는 인코딩이 규격에 없어, UTF-8·EUC-KR 복원을 시도한다.
- 16분음표 격자에 맞지 않는 리듬(3연음 등)은 가장 가까운 16분음표로 맞춘다. 시작 위치가 격자에서 크게 벗어난 음표가 10%를 넘으면 경고한다. 3연음 지원은 2차 버전 후보.
- 마디 중간의 템포 변화는 가장 가까운 마디 시작으로 옮긴다 (경고 표시). 세기(velocity), 페달, 피치 벤드는 악보에 반영하지 않는다.
- **한글 파일 이름은 NFC(합쳐진 형태)로 바꿔 쓴다.** 맥은 파일 이름을 자음·모음이 분리된 형태(NFD)로 돌려주는 경우가 있는데, 이 글자는 PDF용 글꼴에 없어 제목에서 한글이 지워지고 Finale에서도 제목이 깨진다. 파일 이름·트랙 이름·입력한 제목·PDF에 그리는 글자 모두에서 바꾼다 (`readMidi.ts`, `settings.ts`, `outlineText.ts`, 회귀 시험 있음).
- opentype.js 2.0의 글자열 배치·경로 변환(`getPath`, `toPathData`)은 세 글자 이상에서 `NaN`을 만드는 경우가 있어, 글자를 하나씩 이어 붙이고 경로 문자열을 직접 쓴다 (`outlineText.ts`, 회귀 시험 있음).
- OSMD는 템포 표시만 `14pt`·`times`·`xml:space="preserve"`로 그려서 svg2pdf가 PDF에 숫자를 빠뜨린다. `exportPdf.ts`의 `normalizeText`가 변환 직전에 형식을 맞춘다. OSMD를 올릴 때 다시 확인할 것.
- 브라우저 화면 시험(Playwright)은 아직 저장소에 없다. 자동 시험은 로직(Vitest)만 있고, 화면은 개발 중 따로 시험했다.

## 개발 검증 메모

MusicXML은 공식 3.1 스키마(`musicxml.xsd`, https://github.com/w3c/musicxml 의 `v3.1` 태그)를 `xmllint --noout --nonet --schema`로 검사해 통과를 확인했다 (앱에는 포함하지 않음).

## 검증 방법

앱에 포함하지 않는 개발용 검증: 공식 MusicXML 3.1 스키마(`musicxml.xsd`, https://github.com/w3c/musicxml 의 `v3.1` 태그)를 `xmllint --noout --nonet --schema`로 검사.

## 사용 환경 (작성자)

Finale 27.4 (Windows). 제목 글꼴은 MusicXML의 `credit-words`에 맑은 고딕(Malgun Gothic)으로 지정한다 (`src/score/toMusicXml.ts`). 한글 제목 정상 표시를 Finale에서 확인함.
화면은 다크 모드 전용이며, 미리보기 악보만 밝은 색으로 그린다. PDF는 흰 종이·검은 악보로 별도 생성한다.

## 알려진 사항

- opentype.js 2.0의 글자열 배치·경로 변환(`getPath`, `toPathData`)은 세 글자 이상에서 `NaN`을 만드는 경우가 있어, 글자를 하나씩 이어 붙이고 경로 문자열을 직접 쓴다 (`outlineText.ts`, 회귀 시험 있음).
- OSMD는 템포 표시만 `14pt`·`times`·`xml:space="preserve"`로 그려서 svg2pdf가 PDF에 숫자를 빠뜨린다. `exportPdf.ts`의 `normalizeText`가 변환 직전에 형식을 맞춘다. OSMD를 올릴 때 다시 확인할 것.
- 처음 내려받는 JS는 약 336KB(gzip 107KB)이고, 악보 그리기(OSMD, 약 1.5MB)·PDF 만들기(약 0.7MB)·음원 분석(AI, 약 1.8MB + 모델)은 쓸 때만 내려받는다 (M7 확인).

- `@tonejs/midi`의 **쓰기** 기능은 조표를 잘못 기록하는 문제가 있다 (읽기는 정상). 피아노 MIDI 저장(M5) 때 조표 기록은 직접 검증한다.
- MIDI 텍스트(트랙 이름)는 인코딩이 규격에 없어, UTF-8·EUC-KR 복원을 시도한다 (`src/midi/readMidi.ts`).
- 16분음표 격자에 맞지 않는 리듬(3연음 등)은 가장 가까운 16분음표로 맞춘다. 시작 위치가 격자에서 크게 벗어난 음표가 10%를 넘으면 경고를 표시한다. 3연음 지원은 2차 버전 검토.
- 마디 중간의 템포 변화는 가장 가까운 마디 시작으로 옮긴다 (경고 표시).
- 세기(velocity), 페달, 피치 벤드는 악보에 반영하지 않는다.
- 성부는 먼저 시작한 음이 1성부가 된다. 낮은 음이 먼저 시작하면 그 뒤 선율이 2성부(줄기 아래 방향)가 될 수 있다. (피아노 합치기 M4에서 보정 예정)
